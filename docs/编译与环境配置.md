# 编译与环境配置

本指南适用于 [LaTeX 学习笔记模板](../LaTeX_学习笔记模板/)。以下命令都在该模板目录执行；仓库根目录没有 `main.tex`。

## 依赖

使用 TeX Live，确保包含 XeLaTeX、latexmk、BibTeX、ctex、Fandol、natbib、gbt7714、amsmath、pgfplots、tcolorbox、siunitx、hyperref 等宏包。完整安装通常已包含这些组件。模板使用 TeX Live 的 Fandol 中文字体，无需绑定 Windows 系统字体。

VS Code 用户另装 LaTeX Workshop，并通过“打开文件夹”选择 `LaTeX_学习笔记模板/`，让模板内 `.vscode/settings.json` 生效。

## 命令行编译（Windows、macOS、Linux）

```sh
latexmk main.tex
```

`latexmkrc` 指定 XeLaTeX，并自动处理参考文献及交叉引用。输出统一为：

```text
build/main.pdf          # 阅读与预览
build/main.synctex.gz   # 源码与 PDF 跳转
build/main.log          # 排错
```

也可显式选择引擎：

```sh
latexmk -pdfxe -synctex=1 -interaction=nonstopmode -halt-on-error main.tex
```

清理辅助文件而保留 PDF：

```sh
latexmk -c main.tex
```

`latexmk -C main.tex` 还会移除 `build/main.pdf`；脚本额外复制到模板目录的 `main.pdf` 不在该清理范围内。

## Windows 初始化脚本

从 [整理产物的脚本](../整理产物的脚本/README.md) 中任选 `.bat` 或 `.ps1`，放在实际主文件同级目录，两个文件都能独立完成全部功能。

双击 `.bat`，或运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup-latex.ps1"
```

脚本会先归档散落的辅助文件及 `build/` 中的旧缓存，再备份并修复项目与上一级的 `.vscode/settings.json`，以及项目的 `latexmkrc` / `.latexmkrc`，最后检查环境并编译。PDF 按实际主文件名生成，辅助文件统一放进 `build/`。

```powershell
.\setup-latex.bat -MainFile "课程 笔记.tex"
.\setup-latex.bat -ConfigureOnly
.\setup-latex.bat -CleanOnly
.\setup-latex.bat -ProjectOnly
```

`-ConfigureOnly` 清理并修复配置但不编译；`-CleanOnly` 只清理旧辅助文件；`-ProjectOnly` 跳过父目录配置。主文件不叫 `main.tex` 也可使用，多个入口时用 `-MainFile` 指定。

原辅助文件可在 `build/legacy/` 找回；配置文件备份使用 `.backup-时间戳` 后缀。即使未安装 TeX Live 或后续编译失败，已经完成的清理和配置修复仍然生效。

完整编译需要 latexmk 4.86 或更新版本。脚本优先使用 PATH 中的 TeX Live，也支持 `TEXLIVE_ROOT` / `TEXDIR` 及常见安装位置；必要时保留初代脚本的用户 PATH 修复功能。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 找不到 `xelatex` / `latexmk` | 检查 TeX Live 安装与 PATH，重新打开终端或 VS Code |
| 缺少 `.sty` 或 Fandol 字体 | 使用 TeX Live Manager 补齐相应宏包和字体 |
| 找不到主文件 | 传入项目目录或实际 `.tex` 路径；多个主文件时使用 `-MainFile` |
| 找不到正文或附录 | 检查 `main.tex` 中的 `chapters/01-正文/`、`chapters/02-附录/` 路径和文件名 |
| 中文乱码 | 源码保存为 UTF-8，使用 XeLaTeX |
| 插图缺失 | 检查 `media/` 中的文件名与大小写，Linux 区分大小写 |
| 引文或公式显示问号 | 使用 latexmk 完成多轮编译，核对文献键和标签 |
| 不知道 PDF 在哪里 | 在 `build/` 查找与主文件同名的 PDF；脚本及 VS Code 配方还会复制一份到主文件目录 |
| `.ps1` 被执行策略拦截 | 使用上面的 `powershell.exe -ExecutionPolicy Bypass -File ...`，仅作用于该次进程 |

模板中的 PNG/JPG 与 pgfplots 图形不需要 shell escape。若新增 SVG，建议先导出为 PDF 或 PNG；使用 `\includesvg` 则需自行配置 svg 宏包、Inkscape 与相应编译选项。
